# Print on the K2

Two tools, both through `tools/config.py` (`PRINTER` is the address):
- `tools/orca.py` slices with OrcaSlicer's CLI in about 5 s;
- `tools/k2.py` drives the printer over its stock Moonraker API (Klipper's HTTP API, port 7125, no login).

Never kill Orca by image name: he often has it open.

## 1. Before anything

- `python tools/k2.py status`. If it isn't `standby`, `complete` or `cancelled`, a print is running.
  Don't touch it, and ask him before changing the part it is printing (CLAUDE.md).
- If the part still has open guesses, say so before he prints it.
- Print from `head-v2/out/...`. Never from a `superseded - ...` folder.

## 2. Slice

```
python tools/orca.py head-v2/out/print-pan/base.stl
python tools/orca.py part.stl --set layer_height=0.24 --set wall_loops=3 --name part_draft
```

- **Defaults** are his own Creality Print settings: 0.20 mm layers, 2 walls, 15 % grid infill, tree supports
  at 30°, PLA at 220/50 °C, textured PEI plate, max flow 12 mm³/s. `--set` takes Orca's option names. It
  refuses a name no preset has.
- **Test parts in PLA: add `--draft`.** It's about 20% faster: wall acceleration 8k/10k, slim tree supports, 10%
  infill, 3 top layers, flow 18. The head set went 3h41m → 2h59m. The measurements and the rejected options
  are in the comment on `orca.DRAFT`. Don't use snug normal supports to save time: they pack the cradle's
  wire hole and the drum's notch. Slim tree supports get their own layer heights between the part's, so the
  layer count roughly doubles.
- **Orientation:** one part keeps its drawn orientation, centred on the bed. Several parts go to Orca's
  arrange, which may turn them.
- **Output** goes to `head-v2/out/gcode/<name>_orca_PLA_<time>.gcode`. Read the summary line: time, grams,
  layers, height, supports, and `start G-code ok`. Don't send a file with `start G-code ok: False`.
- **The start G-code** is Creality Print's single-spool start, the one the printer has always run. Orca's own
  K2 profile primes along the bed's very edge. The header says "generated by Creality_Print", as Orca's
  profile does, for the printer's job parser. The real slicer is on the line after the header.
- **Times run long:** Orca's tree supports use about 25 % more line than Creality Print's. On the pan base
  that was 2h52m and 52 g, against 2h23m and 45 g. The part's own paths match.

## 3. Send and start

```
python tools/k2.py upload head-v2/out/gcode/<file>.gcode
python tools/k2.py start <file>.gcode --bed-clear
```

- **Bed check:** nothing can see the bed (the camera isn't on Moonraker). Before every start, ask Zach
  whether the plate is empty and the right filament is loaded. Pass `--bed-clear` only after he says yes.
  `start` also refuses if the printer is busy, the file isn't on it, or the sensor sees no filament.
- **Filament:** the CFS (the 4-spool filament box) reads `disconnect`, so he feeds from the side spool
  holder. If the box ever reads connected, check which slot the job's `T0` pulls before starting.
- **After the start:** run `status` once more to confirm it's heating, or on layer 1. Then stop.
  **Don't watch the print.** The K2 has its own AI failure detection, and he asked not to spend tokens on
  progress reports. Check `status` only when he asks.

## 4. During a print, on his word

`python tools/k2.py pause | resume | cancel`. These run Creality's own PAUSE, RESUME and CANCEL_PRINT
macros. Cancelling can't be undone: confirm it with him first unless he said "cancel" himself.

## Things learned (2026-10-03)

- Moonraker's metadata calls every file "Unknown", Creality Print's too, and this build has no `metascan`.
  Read time and grams from the G-code itself (`orca.py` does).
- The upload's reply isn't wrapped in `result`. `k2.py` handles it.
- Don't delete files on the printer. An upload with the same name replaces the old one.
- The CLI writes its real error to `00000.log` in its working folder. `orca.py` prints it when a slice fails.
- Orca's CLI can't render thumbnails (no OpenGL), so the K2's screen shows no picture for these files.
- Later idea (Zach): the robot swaps the plate when a print finishes. Not built.

## Things learned (2026-10-04)

- **Small parts need a raft** (Zach): a plate of snap pins, camera posts and the tab block came loose without
  one. Slice them with `--set raft_layers=3` (about +2 min on that plate).
- `cancel` can take longer than 10 s to answer while CANCEL_PRINT runs; `k2.py` now waits 60 s. Read
  `status` after it either way.
